## Where the bench stands

- **Rig**: ESP32 (classic) + E07-M1101D CC1101, firmware `fw=1.0.0`, CP2102 on `/dev/ttyUSB0` at
  115200. Text command set: PING/INFO/CFG/RX ON|OFF/TX OPT|RAW/STOP/SCAN/RSSI/STATS/CAP/REG/REGS.
- **Rig RX: verified good.** Reads a −57.5 dBm carrier on demand; captures synthetic PT2262 frames
  as 53 frames with *exactly* 26 edges each and clean 1T/3T widths at 350/1050 µs.
- **Rig TX: UNVERIFIED — this is the one open question.** Run
  `sudo /tmp/ys1venv/bin/python rig_tx_verify.py` with both devices plugged in (dongle as receiver).
  The earlier "the ESP32's transmit does not radiate" claim was **retracted**: it was measured with
  the dongle as receiver *on a bad antenna*. Never repeat it untested.
- **Dongle TX: verified.** −48.5…−57.5 dBm into the rig; sends synthetic PT2262 frames on command.
  The PA must be set explicitly (`setMaxPower()` **and** `setPower(0xC0)`) or it reports success and
  radiates nothing — `setMdmModulation` alone does not set PA power.
- **Dongle RX: works — with a decent antenna.** −67 dBm peak, 40.5 dB spread, demodulating bytes.
  The earlier "deaf receiver / transmit-only" verdict was measured with a DIY quarter-wave whip with
  no counterpoise; that was the antenna, not the radio. Caveat: rflib's RX is unstable on long runs
  (`USBTimeoutError(110)`) and then needs a **physical replug** — never USB-reset the dongle.
- **Gate remote: dead.** Five sessions on the rig (single/repeated/both-buttons, contact range,
  squelch wide open at −110, plus a 433.0–435.0 sweep) produced nothing. The operator's **Autel
  KM100** also detected no signal, but treat that as supporting only: the KM100 is a car-key tool
  (its own feature matrix lists "Garage Remote: X"). Fix path: fresh cell, then the unit.
- **Operator's car key: ~315 MHz** (KM100 read 312 & 314) — outside the E07's 387–464 MHz range, so
  the rig can never see it. Do not use it as a 433 reference. The dongle (CC1111: 300–348 MHz) could.

## Two findings not to re-derive

1. **`CFG BW=58`, not the firmware's 100.** At 100 kHz the same OOK transmission arrives as 800+
   chatter edges with smeared widths (nothing decodable); at 58 kHz it is 26–32 edges with clean
   1T/3T. It costs ~1.5 dB of level. **Volatile** — the rig's image restores `bw=100` on boot/RESET,
   so set it per session or in the host tool.
2. **A loose MISO (E07 pin 7) presents as write-OK / read-corrupt.** The firmware keeps configuring
   the radio while RSSI, REGS, STATS and MARCSTATE all lie — GDO0 (pin 3) is a separate pin, so the
   *pulse* path still works and only the numbers are wrong. Signature: RSSI reads landing on exactly
   **−74.0 dBm** (raw 0x00 = no data). Found by the operator as a loose pin plus a jumper held by
   solder rather than wire; proved fixed with `spi_stress.py` (all read paths consistent).

## Gotchas that cost time tonight

- The firmware parses `REG` arguments as **DECIMAL**: TEST0 (0x2E) is `REG 46 11`, not `REG 2E 0B`.
  Hex input silently writes a different register.
- **Never open `/dev/ttyUSB0` from a second process while a capture owns it** — it kills the
  capture with "device reports readiness to read but returned no data".
- Scripts run under `sudo`: `~` expands to `/root`. Pass absolute output paths.
- `pkill -f <pattern>` matches its own command line — bracket it (`[p]attern`), and **do not repeat
  the plain name anywhere else in the same command**: an `echo` mentioning the script name was enough
  to make the command SIGTERM itself. Kill by pid when in doubt.
- `edge_hunt.py` re-parks the rig on 433.920 when it finishes; earlier it left the rig on the last
  swept frequency and the next reading looked like a dead receiver.
- A DIY whip with no counterpoise contributes ~0 dB and swings up to 18 dB when a hand comes near:
  **hands off, fixed geometry** for every comparison.

## Tools in `skills/rf-security-research/scripts/`

| tool | what it does |
|---|---|
| `bench_selftest.sh` | one command, ~75 s, 4-point bench sanity: chip identity, SPI read paths, dongle-carrier level at the rig, synthetic-frame capture. Prints "Bench is sound" or names the fault. |
| `spi_stress.py` | MISO integrity: INFO/REGS/RSSI stability, flags −74.0 dBm raw-0x00 reads. |
| `remote_test.py` | capture + classify a remote: frames, level vs the noise ceiling, edges/frame, 1T/3T histogram, repeats. |
| `remote_watch.py` | continuous watcher for a pile of remotes: timestamps every burst with level, edge count and structure. |
| `rig_tx_verify.py` | **the open test**: dongle listens, rig transmits, verdict on whether the rig radiates. |
| `edge_hunt.py` | frequency hunt using the level-independent edge counter (RSSI sampling misses short bursts). |
| `ys1_send_code.py` | dongle sends a synthetic PT2262 frame (T configurable) — the bench's known-good "remote". |
| `ys1_tx_carrier.py` | dongle holds a steady carrier with the PA forced (setPower(0xC0)). |
| `ys1_stop_tx.py` | forces the dongle IDLE and reports MARCSTATE. Run it after killing ANY dongle TX script — a killed rflib TX keeps radiating, and once jammed a live capture for 27 s. |

Rebuild the venv after a reboot (it lives in /tmp):
