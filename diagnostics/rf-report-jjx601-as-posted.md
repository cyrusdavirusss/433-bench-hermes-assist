Comprehensive System Overview and Diagnostic Context
The evaluation of radio frequency (RF) access control mechanisms requires precise instrumentation, rigorous software execution, and a deep understanding of spectral regulations. The provided diagnostic log details an exhaustive testing session conducted in Endeavour Hills, Victoria, Australia. The primary objective of the session was the spectral capture and analysis of a generic aftermarket gate remote, identified by its internal printed circuit board (PCB) nomenclature as R433 33X601 VR IC ATEL80 24C02N SU27 D and commercially designated as the JJX601.
The analytical bench utilized two distinct hardware transceivers: an ESP32 microcontroller integrated with an E07-M1101D transceiver module (utilizing the Texas Instruments CC1101 silicon), and a YARD Stick One USB dongle (utilizing the Texas Instruments CC1111 architecture)1. The session was mediated by a custom Python-based graphical user interface, designed to orchestrate wideband spectral sweeps, coordinate transmission and reception states, and measure the Received Signal Strength Indicator (RSSI) of the local environment.
Despite the resolution of multiple complex software and firmware anomalies, the bench instrumentation failed to detect any RF emissions from the JJX601 remote control within the swept frequency domains of 281–361 MHz and 378–481 MHz. The log posits several ranked hypotheses for this lack of detectable emissions, including transmission outside the monitored spectral windows, legacy frequency utilization (27 MHz or 40 MHz), or an erased internal EEPROM state that precludes RF modulation. This report provides an exhaustive, domain-expert analysis of the software architecture corrections, the physical limitations of the CC1101/CC1111 phase-locked loop (PLL) synthesizers, the embedded logic of the 24C02 memory module, the Australian regulatory framework governing these devices, and the spectral methodologies required for subsequent investigations.
Software Architecture and Diagnostic Interface Stabilization
The reliability of any RF diagnostic bench is fundamentally predicated on the stability of its software control plane. The log documents a series of critical software bugs and their subsequent resolutions. Analyzing these software corrections is essential to validating the integrity of the physical RF measurements that followed.
The initialization of the testing environment was initially hindered by a fatal stream redirection error. The log indicates that the Python runtime terminated the ESP32 connection path because sys.stdout resolved to a None type within a windowed application context. When a Python application is executed as a windowed or headless process (often achieved via pythonw.exe or frozen binaries), standard input and output streams are entirely detached from the operating system console. Consequently, any internal library—such as the rf433.colour_enabled() routine—that attempts to invoke the .isatty() method on a non-existent standard output stream will trigger a fatal AttributeError. The architectural remediation for this involves either forcing the stream to a null device, such as os.devnull, or implementing thread-safe custom stream wrappers that safely swallow console output, thereby allowing the underlying peripheral initialization to proceed unimpeded.
Further complicating the graphical interface was a threading deadlock associated with variable reads. The log notes that attempting to read Tk variables from asynchronous worker threads resulted in failures, as the main thread was not actively processing its event loop. The Tkinter GUI toolkit, which serves as the standard interface layer for Python applications, operates on a strictly single-threaded event loop architecture. When background worker threads attempt to modify or read StringVar or IntVar objects directly, the GUI framework experiences race conditions, deadlocks, or immediate segmentation faults. The stabilization of the bench software was achieved by refactoring the architecture so that background threads process raw data values and utilize thread-safe queuing mechanisms to dispatch updates to the main execution thread, ensuring that all interface state changes occur safely within the primary event loop.
The integration of the YARD Stick One via the rflib library revealed a critical misunderstanding of asynchronous USB context management. The log details that the tx_once.py script failed to transmit a requested 200-repeat payload because the RExmit function executes asynchronously. When the rflib Python wrapper issues a transmission command, it streams the payload into the hardware FIFO buffer of the CC1111 and transitions the transceiver state machine to the transmit (TX) state. Because the software function does not block until the transmission completes, the Python script advanced immediately to its termination sequence, executing sys.exit() in approximately 0.03 seconds. This rapid termination gracefully destroys the libusb context, forcing a hardware reset on the dongle and flushing the FIFO buffer long before the 200 repeats could be serialized over the air interface. The creation of a sustained transmission script, which actively holds the USB interface open while monitoring the hardware state, correctly resolved this anomaly and validated the bench's transmission capabilities.
Finally, the diagnostic software required stringent calibration of its digital signal processing parameters. The operator observed that the CC1101 firmware silently rejected requests to expand the receiver bandwidth beyond 800 kHz, causing the software to default to a 100 kHz setting. The channel filter bandwidth of the CC1101 is strictly governed by the system clock frequency and the decimation ratio programmed into the MDMCFG4 hardware configuration register4. The theoretical maximum programmable bandwidth for this silicon is approximately 812 kHz4. Requesting a bandwidth of 300,000 kHz constitutes an extreme out-of-bounds parameter, triggering a silent hardware rejection or firmware-level exception handling. By adjusting the software to request a valid 650 kHz bandwidth, the operator successfully widened the intermediate frequency (IF) filter. This wider filter subsequently captured a larger integration of thermal background noise, raising the local noise floor to approximately -60 dBm, which aligns precisely with standard thermodynamic noise calculations for wideband receivers. Additionally, the log notes that reading the Received Signal Strength Indicator (RSSI) on an idle radio yielded garbage values (e.g., -138 dBm). The CC1101 calculates RSSI based on the current gain setting in the receiver chain; if the transceiver state machine is in the IDLE state rather than the RX state, the analog-to-digital converter (ADC) is disabled, and the RSSI register contains invalid, uncalibrated data1. Enforcing a state-aware polling mechanism that only reads RSSI when the radio is actively settled in RX mode ensured that the recorded baseline floor of -112.5 dBm to -113.5 dBm was highly accurate.
Transceiver Hardware Dynamics and Synthesizer Limitations
With the software interface stabilized, the physical capabilities of the RF instrumentation must be evaluated to address the hypothesis that the JJX601 remote might operate on legacy frequencies (27 MHz or 40 MHz). Both the ESP32-driven E07-M1101D and the YARD Stick One rely on highly integrated, sub-1 GHz Texas Instruments transceivers (the CC1101 and CC1111, respectively)1.
The tuning capability of these chips is dictated by an internal fractional-N Phase-Locked Loop (PLL) frequency synthesizer4. The desired center frequency is configured by writing a 24-bit frequency control word across three specific hardware registers: FREQ2, FREQ1, and FREQ05. The internal Voltage-Controlled Oscillator (VCO) generates the required frequency based on the reference crystal oscillator (typically 24 MHz or 26 MHz) multiplied by this fractional word.
However, the physical design of the VCO imposes strict upper and lower bounds on the tunable spectrum. The datasheets for the CC1101 and CC1111 architecture explicitly define the supported operating bands, which are dictated by the resonance characteristics of the on-chip inductor-capacitor (LC) tank circuits.

Microcontroller and EEPROM Interplay in Duplicator Remotes
The device under test is marked R433 33X601 VR IC ATEL80 24C02N SU27 D. The commercial designation JJX601 identifies this device as a generic, aftermarket learning-code duplicator remote19. These devices are manufactured globally, particularly in Chinese electronics hubs, to serve as replacements for a wide array of fixed and learning-code garage and gate systems.
Unlike original equipment manufacturer (OEM) remotes, which are programmed with a specific cryptographic seed or fixed payload at the factory, duplicator remotes are shipped effectively blank. The architecture of the JJX601 relies on a central Microcontroller Unit (MCU) interfaced with a 24C02 serial Electrically Erasable Programmable Read-Only Memory (EEPROM) chip via the Inter-Integrated Circuit (I2C) protocol21.
The 24C02 I2C Memory Architecture
The 24C02N component provides 2 Kilobits (256 bytes, organized as 256 x 8 bits) of non-volatile memory21. In a standard implementation, the MCU acts as the I2C master, generating the clock signal on the SCL line, while the 24C02 acts as the slave device on the SDA line. The I2C address for the 24C02 is inherently configured by its hardware pins, typically responding to the hex address 0x50 (or 0xA0 in 8-bit addressing schemes)23.
When a user initiates the cloning procedure—usually by placing an original working remote back-to-back with the JJX601 and holding a specific button combination—the JJX601's internal RF circuitry enters a receive/sniff mode26. The MCU digitizes the incoming On-Off Keying (OOK) or Amplitude Shift Keying (ASK) waveform, extracting the pulse widths, synchronization bits, and the actual digital payload (often a 24-bit structure emulating older PT2262 or EV1527 encoder ICs)20. The MCU then initiates an I2C write sequence to the 24C02 at address 0x50, writing the captured payload and timing coefficients into the non-volatile memory array21.
During normal operation, pressing a button wakes the MCU from deep sleep. The MCU reads the button state, queries the 24C02 EEPROM at specific memory offsets to retrieve the stored payload for that specific button, configures the RF oscillator, and toggles the GPIO pin connected to the power amplifier to broadcast the cloned signal19.
The "Unprogrammed State" and LED Decoupling
The diagnostic log posits a highly insightful theory: "an unprogrammed or reset copy remote transmits NOTHING while its LED still blinks."
This phenomenon is a direct consequence of the firmware logic programmed into the duplicator's MCU. The JJX601 features a user-accessible memory wipe function, activated by holding the A and B buttons simultaneously until the LED flashes, releasing B, and pressing B three times26. Executing this sequence commands the MCU to execute a page-write sequence across the entire 24C02 EEPROM, overwriting the memory array with 0xFF or 0x0027.
If a user presses a transmission button while the EEPROM is in this completely wiped state, the MCU reads a null or invalid payload from the I2C bus. Because there is no mathematical pulse-width data or binary payload to modulate, the MCU's transmission subroutine simply terminates early or enters a null loop. However, the subroutine responsible for illuminating the status LED is generally decoupled from the RF transmission logic to provide immediate tactile and visual feedback to the user19. Therefore, the MCU drives the GPIO pin connected to the LED, causing it to blink, but entirely fails to drive the GPIO pin connected to the Surface Acoustic Wave (SAW) resonator or RF oscillator.
This architectural decoupling results in a remote that appears entirely functional to the human eye but emits absolute zero radio frequency energy into the environment. Given that the bench's spectral sweep demonstrated a completely flat noise floor during the 45-second test, Ranked Cause (3)—an unprogrammed or factory-reset copy remote—stands as the most scientifically probable explanation for the absence of RF emissions.
Regulatory Framework: ACMA Class Licences and Spectrum Allocation
To evaluate the log's second ranked cause—that the original gate system operates on a legacy 27 MHz or 40 MHz band outside the CC1101's physical tuning range—the regulatory environment specific to Endeavour Hills, Victoria, must be thoroughly analyzed. All radiocommunications in Australia are governed by the Australian Communications and Media Authority (ACMA) under the legislative authority of the Radiocommunications Act 199229.
Short Range Devices and the LIPD Framework
Garage door openers, gate remotes, and personal wireless alarms are classified as Short Range Devices (SRDs)32. Due to their low power output and high ubiquity, ACMA does not require individual users to hold apparatus or spectrum licenses for these devices. Instead, they are authorized under a blanket regulatory instrument known as the Radiocommunications (Low Interference Potential Devices) Class Licence (LIPD)29.
Equipment operating under the LIPD Class Licence must strictly adhere to the technical performance parameters delineated in the AS/NZS 4268 standard ("Radio equipment and systems - Short range devices - Limits and methods of measurement")31. For devices operating in the highly congested 433 MHz ISM (Industrial, Scientific, and Medical) band, the specific allocation is 433.05 MHz to 434.79 MHz, centered at 433.92 MHz17. The AS/NZS 4268 standard and the LIPD class licence restrict transmitters in this band to a maximum Equivalent Isotropically Radiated Power (EIRP) of 25 milliwatts (mW)17.
The physical markings on the JJX601 remote (R433 and generic 433 MHz marketing specifications) strongly indicate it was designed and calibrated to operate within this 433.92 MHz SRD allocation19.
The 2025 LIPD Modernization and Legacy Band Ramifications
The regulatory landscape is currently undergoing a significant transition. The ACMA has recently finalized the Radiocommunications (Low Interference Potential Devices) Class Licence 2025, which replaces the outgoing 2015 iteration, effective October 1, 202538. The 2025 modernization introduces critical spectrum allocations for emerging technologies, including Wireless Multi-Channel Audio Systems (WMAS) in the 520–694 MHz band, high-power digital modulation transmitters in the 5150–5250 MHz band, and advanced Radio Local Area Network (RLAN) operations in the 6425–6585 MHz band to support Wi-Fi 6E and Wi-Fi 7 deployment38.
While modernizing the upper spectrum, the ACMA continues to manage legacy frequency allocations. Historically, prior to the mass commercialization of 433.92 MHz SAW resonators, Australian gate automation systems heavily utilized the 27 MHz and 40 MHz bands.

Advanced Spectral Reconnaissance and Direct Sampling Methodologies
To empirically determine whether the target environment relies on legacy frequencies, the log outlines a progression to wideband spectral analysis utilizing an RTL-SDR dongle. Because the ESP32/CC1101 and YARD Stick One are physically limited by their PLL VCOs from tuning below 300 MHz1, the introduction of Software-Defined Radio (SDR) instrumentation is the only scientifically valid method to proceed.
Standard RTL-SDR dongles, widely utilized for RF diagnostics, are typically built around the Rafael Micro R820T2 tuner integrated circuit coupled with a Realtek RTL2832U demodulator and ADC43. The R820T2 heterodyne tuner is designed to sweep a standard range of approximately 24 MHz up to 1.76 GHz44.
However, attempting to measure a 27.145 MHz signal using the standard tuning mode of the R820T2 introduces significant diagnostic risk. At 24 MHz to 28 MHz, the internal PLL of the R820T2 is operating at the absolute lower threshold of its stability curve. Measurements taken at this extreme edge often suffer from severe attenuation, non-linear phase noise, and drastically reduced sensitivity, potentially causing the operator to miss a weak remote control signal45.
To accurately and reliably capture signals in the legacy 27 MHz and 40 MHz bands, the operator must bypass the R820T2 tuner entirely. This is achieved via a technique known as HF Direct Sampling (Q-Branch)43.

In Direct Sampling mode, the RF signal from the antenna is routed away from the R820T2 tuner and fed directly into the Q-branch input pins of the RTL2832U Analog-to-Digital Converter43. This allows the SDR to leverage the Nyquist-Shannon sampling theorem directly on the baseband HF spectrum, achieving high-fidelity signal capture from 500 kHz up to 24 MHz43. While 27 MHz sits slightly above the strict 24 MHz cutoff of standard direct sampling, modern RTL-SDR Version 3 and Version 4 implementations utilize software-switchable bias-tees and internal upconverters that seamlessly expand this direct sampling fidelity up to 30 MHz, entirely eliminating the need for destructive hardware soldering modifications on the PCB47.
By utilizing decoding frameworks such as rtl_433—which natively supports the demodulation of OOK, ASK, and FSK pulse-width encoded telemetry—the operator can command the RTL-SDR to monitor a wide waterfall covering 27.000 MHz to 28.000 MHz49. When the original, functioning gate remote is triggered in proximity to the SDR antenna, the resulting spectrogram will definitively prove whether the access control infrastructure relies on ACMA legacy bands.
Strategic Recommendations and Conclusions
The execution of the RF diagnostic session recorded in the log demonstrates a high degree of technical rigor. The meticulous identification and resolution of software threading deadlocks, asynchronous USB context teardowns, and transceiver bandwidth limitations resulted in a highly calibrated testing environment. The recorded environmental noise floor of -113 dBm confirms the sensitivity of the receiver chains.
The failure to capture RF emissions from the JJX601 remote is definitively not an artifact of poor instrumentation or measurement error; rather, it is a consequence of the device's current memory state or environmental mismatch. Based on the integration of hardware architectures, EEPROM logic, and the Australian regulatory spectrum, the following conclusions are established:
Hardware Limitations of the Bench: The CC1101 and CC1111 transceivers are fundamentally incapable of tuning to legacy 27 MHz or 40 MHz frequencies due to the physical resonance limits of their internal Phase-Locked Loop (PLL) VCOs. Any attempt to force these frequencies results in a fatal FS_LOCK state machine stall.
The EEPROM Null-State Hypothesis: The JJX601 remote utilizes a 24C02 I2C EEPROM to store cloned payloads. A factory reset overwrites this memory with null data. Because the status LED is driven by a separate GPIO subroutine than the RF oscillator, an unprogrammed remote will flash its LED to indicate battery power, while the power amplifier remains deactivated, emitting zero RF energy.
Regulatory Misalignment: If the original gate system in Endeavour Hills relies on ACMA legacy CB-adjacent bands (27.045 MHz to 27.195 MHz), the 433.92 MHz JJX601 duplicator is physically incapable of sniffing, decoding, or cloning the original remote, leaving the duplicator in the aforementioned blank state.
The most viable next action is to isolate the remote's functionality by executing a test-clone using a known-good 433.92 MHz transmitter (e.g., a standard EV1527 keyfob). If the bench successfully detects the subsequent transmission, it definitively proves that the JJX601's RF hardware is operational and that the silence was due to an empty EEPROM. If the JJX601 proves functional but still cannot open the local gate, the deployment of an RTL-SDR operating in Direct Sampling mode is the required next step to spectrally analyze the original gate remote and confirm the presence of 27 MHz or 40 MHz legacy infrastructure.
